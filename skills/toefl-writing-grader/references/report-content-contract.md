# Report Content Contract

Load this reference when defining the information shown to students, parents, or teachers. It governs content boundaries; typography, color, charts, pagination, and visual themes belong to the report-design workflow.

## Shared facts

All reader views use the same validated scores, evidence, quantitative inputs, and article records. A parent or teacher view must not invent a separate scoring map.

## Student view

Show the result, the most important evidence-backed findings, and a small set of executable revision actions. Include original text only when the requested report format supports readable annotation.

## Parent view

Show overall performance, the main strength, the highest-priority gaps, and concrete next actions in accessible language. Do not expose internal rule codes, unsupported examples, or unnecessary student-text detail.

## Teacher or controller view

Show evidence links, dimension scores, confidence or missing-data status, teacher overrides, and validation records needed for review and longitudinal planning.

## Output boundary

- Do not require a specific chart type, Glass style, weekday theme, or fixed card count.
- Do not force a one-page report when readable content requires more space.
- Use only submitted task types; represent missing task types as unavailable rather than low-scoring.
- Validate identity and score consistency across artifacts actually emitted in the current run.
