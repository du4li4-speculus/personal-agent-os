# 验证层

验证是交付门禁，不是生成后装饰。任一阻断项失败，都不能交付报告或把缺口伪装成低分。

## 数据门禁

1. `source_bundle.json` 通过 schema，所有原始来源有摘要和适配器 provenance。
2. `evidence.json` 与 bundle id 一致；题目、正文、批注和图片缺口均显式记录。
3. assessment 的每篇 piece 有六个分数、evidence ids、原文边界和题型；雷达与详细评价同步。
4. `quant_inputs` 数量与 pieces 中对应题型数量一致；量化雷达不得手填。
5. 预测总分、舍入规则和单题型省略规则通过契约；教师 override 有独立记录且 `rule_update=not_automatic`。

## 成品门禁

826–831 输入迭代与最新可见成品形成的验收基准如下：

- 学生版首屏清楚显示邮件、学术、折算总分三张卡；显示总分时带造句错误基数。
- 学生版能看到当前提交的逐篇原文和逐维证据，原文只出现一次；六维图和详细分数一致。
- 家长版实际为一页，包含三张卡、两类六维图、量化指标雷达、学术能力光谱、一个最大优点、两个待提升方面和两条动作。
- 读者文案不暴露内部 CEFR、带圈数字、规则来源或教师内部术语；家长版不出现学生原句示例。
- 单题型、多篇同题型、缺题型和 OCR 未完成均按契约处理，不通过删字段绕过。

## 标准来源说明

提供的参考目录没有明确标出 `2026-09-01` 的独立标准文件；本 Skill 因此采用最新 canonical `SKILL.md`，并以编号 826–831 的输入演进和可核对的 9 月 2 日学生/家长成品作为验收证据。若后续出现明确的 9 月 1 日定版，应新增回归样例并更新本文件，而不是静默覆盖当前规则。

契约记录见 `schemas/validation_record.schema.json`。
